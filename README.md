# Airlines Process Wiki

A static, browsable wiki of airline business processes, written for SAP transformation / consulting work ("SAP Consulting - Airlines Process Wiki v1.0"). Every process is documented down to **L4 step level** (role, system, input, output, KPI, pain point, decision gate, exception flag) and has a BPMN-style flow diagram.

**Live site:** https://ghatk047.github.io/airline-process-wiki/

It is aimed at consultants, process architects and solution designers who need a starting-point catalogue of airline processes and the systems that typically support them (Amadeus, Sabre, Jeppesen, AMOS, SAP S/4HANA and so on).

> **Disclaimer.** All content is synthetic. It was generated by LLM agents (the Claude CLI and, for the later expansion batches, a local Qwen model via Ollama) from general industry knowledge, not from any airline's actual processes, data or systems. It is not affiliated with or endorsed by any airline or by any vendor or standards body named in it (Amadeus, Sabre, SAP, IATA, ATPCO, OAG and others). Product and organisation names are used only to identify generic industry tooling. KPI targets and regulatory references have not been independently verified; review before using in a client deliverable.

Each process page has a BPMN process-flow diagram, process attributes (ID, domain, L2 group, L3 name, swim-lane roles, systems and tools), the L4 steps table, KPIs, airline-specific risks and pain points, and inputs/outputs.

## How it works

1. **Data.** `data/processes.json` (`{version, generated, processes[]}`) holds each process: `id`, `l1_domain`, `l1_slug`, `l2_process`, `l2_slug`, `l3_name`, `status`, `run_date`, `wiki_path` and `l4_steps[]`. Each L4 step has `step` (e.g. `1.1`), `name`, `role`, `system`, `input`, `output`, `kpi`, `pain_point`, `decision_point` (Y/N) and `exception` (Y/N).
2. **Diagram.** A Mermaid `flowchart LR` is written to `diagrams/<id>.mmd` and rendered to `assets/img/<id>.png` with `mmdc` (`@mermaid-js/mermaid-cli`).
3. **Pages.** Python scripts read `processes.json` and write the static HTML pages, index pages and search index. There is no framework or bundler; the repo root is the site.
4. **Deploy.** Pushing to `main` triggers `.github/workflows/deploy.yml`, which uploads the entire repo root (`path: '.'`) as a GitHub Pages artifact and deploys it. The workflow can also be run manually (`workflow_dispatch`).

## Building and regenerating locally

Pure page generation needs only Python 3 and the standard library. Diagram rendering needs `mmdc`. Excel/PPTX output needs `openpyxl` / `python-pptx`. LLM generation needs the Claude CLI or a local Ollama server. Install these yourself; none of the commands below install anything.

The commands exist in the scripts (argument parsers or docstrings; `--help` was checked for `build_wiki.py`, `build_slides.py`, `generate_l4_qwen.py` and `generate_ea_qwen.py`; `build_search_index.py` was run once and rewrote `search-index.json` with 545 entries). The full generation pipeline (LLM, `mmdc`, Excel, pptx) was not run end to end. Run commands from the repo root. Many of them **overwrite committed files in place**, so work on a branch and review `git diff` afterwards.

```bash
# Regenerate home page, every L1 index and every L2 index from data/processes.json
python3 scripts/build_index.py

# Regenerate search-index.json from data/processes.json
python3 scripts/build_search_index.py

# Build one process page (index.html) / one 3-slide deck (slides.html)
python3 scripts/build_wiki.py   --process-id NP-SP-03
python3 scripts/build_slides.py --process-id NP-SP-03

# Render one diagram (the same steps run_pipeline.sh uses)
python3 scripts/sanitise_mmd.py diagrams/np-sp-03.mmd
mmdc -i diagrams/np-sp-03.mmd -o assets/img/np-sp-03.png -w 1920 -H 1080 --scale 2 --backgroundColor white

# Write/refresh the Excel catalogue entry for one process
python3 scripts/write_excel.py --process-id NP-SP-03 --json-file path/to/np-sp-03.json

# Rebuild the PPTX (needs python-pptx)
python3 scripts/build_pptx.py
```

| Script | Purpose |
|--------|---------|
| `build_index.py` | Home page plus all L1 and L2 index pages; also writes the sidebar (including the EA Diagrams section) |
| `build_wiki.py` | One process page, `--process-id` required |
| `build_slides.py` | One 3-slide HTML deck (BPMN, attributes, KPIs and pain points); print to PDF from a browser |
| `build_search_index.py` | `search-index.json` for the search box and `search.html` |
| `build_pptx.py` | `data/Airlines_Process_Diagrams.pptx`, one slide per process |
| `create_catalog.py` | Bootstraps `Airlines_Process_Catalog.xlsx`; documented as "run once", so do not re-run it against the committed workbook without a backup |
| `write_excel.py` | Adds a process tab and updates the Index tab; uses `fcntl` file locking |
| `sanitise_mmd.py` | Strips apostrophes, quotes, ampersands and newlines from Mermaid labels before rendering |
| `run_pipeline.sh` | Original orchestrator: picks `Queued` processes, calls the `claude` CLI, renders, updates Excel, wiki, slides and home page, then commits and pushes to `main`. Flags: `--max N`, `--dry-run`, `--id <PID>` |
| `generate_l4_qwen.py` | Expansion generator: Qwen (Ollama, default `http://localhost:11434`) writes only the L4 steps, then the BPMN Mermaid is built deterministically in Python. Flags: `--max`, `--id`, `--dry-run`, `--no-render`, `--rebuild-mmd <PID>`, `--model`. Repo location from env `WIKI_REPO` (default `~/Downloads/airline-process-wiki`) |
| `generate_ea_qwen.py` | EA diagram generator driven by `ea-diagrams/ea_manifest.json`. Flags: `--all`, `--id`, `--no-render`, `--model` |

Several scripts assume the original author's layout (for example `~/Downloads/airline-process-wiki` in `CLAUDE.md` and as the `WIKI_REPO` default). URLs inside `search-index.json` are hard-coded to the `/airline-process-wiki/` Pages base path, so search results will not resolve under a different base path or when served from a local root.

## Contributing and conventions

- Treat `data/processes.json` as the source of truth. Edit data, then regenerate pages and indexes; avoid hand-editing generated HTML, since the next run of `build_index.py` / `build_wiki.py` will overwrite it.
- After adding or changing processes, rerun `build_index.py` and `build_search_index.py`, commit, and push to `main` to deploy.
- Follow the quality bar in `CLAUDE.md` for new L4 content: 10-18 steps grouped into 3-6 phases; at least one decision gate (`decision_point = Y`) per phase, stating the actual question; explicit feedback loops when a gate fails; every step names a concrete system; KPIs carry numeric targets where benchmarks exist; pain points are airline-specific (regulation, vendor or system constraints). The expansion generator targets 12-14 steps per process.
- Mermaid style used by the project: navy start/end ovals (`#003366`), orange decision diamonds (`#ff6600`), phase subgraphs, short node labels, all feedback loops visible. Run `sanitise_mmd.py` before `mmdc`.
- `CLAUDE.md` is partly out of date: its ID table (for example `FO-FD`, `CM-DO`, `GO-RT`, which do not occur in the data) and its `wiki/` output directory do not match the current data and layout. Trust `data/processes.json` and the folder tree over it.
- This repository is public: keep any confidential client information out of it.
