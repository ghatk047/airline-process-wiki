StepL4 Step Name KPI / TargetPain Point / RiskGate
1.1 Extract PNR data for upsell candidate pool Candidate pool coverage ≥95% of eligible bookings extracted Altéa PNR data exports can lag up to 15 min during peak schedule periods, narrowing the actionable upsell window for close-in departures
1.2 Score passengers using willingness-to-pay model WTP model accuracy ≥82% (lift vs. random baseline on holdout set) PROS RM WTP models trained on pre-COVID data can overestimate premium-cabin demand for leisure-heavy route clusters; requires quarterly recalibration
1.3 Check premium cabin inventory for upgrade availability Premium cabin upgrade seat availability query response time <2 sec Real-time seat availability from AltéaRM can conflict with GDS inventory counts when passive segments are not cancelled promptly, creating ghost-availability errors ⚠
1.4 Segment eligible passengers by WTP tier and route High-WTP tier (score ≥70) constitutes ≥30% of total candidate pool Loyalty programme members in lower fare classes are frequently misclassified as low-WTP due to sparse ancillary purchase history in PROS RM
2.1 Generate dynamic upgrade offer price per passenger Average upgrade offer price within 15% of O&D revenue maximisation model output PROS RM dynamic pricing engine does not natively ingest competitor same-day premium fare data, requiring manual competitive adjustment for price-sensitive O&D markets
2.2 Apply ATPCO fare floor and ceiling constraints 100% of published upgrade offers compliant with ATPCO Cat 25 negotiated fare rules ATPCO Cat 25 rule interpretation varies across PSS implementations; non-compliant upgrade offers can trigger GDS mis-pricing alerts and require emergency fare recall ⚠
2.3 Bundle ancillary services with upgrade offer Ancillary attach rate per upgrade offer ≥40% on applicable routes NDC API Gateway bundle assembly fails when ancillary inventory systems (lounge access, seat maps) return timeout errors, forcing fallback to offer-only pricing with no bundle
3.1 Publish upgrade offers via web check-in and mobile app Offer display latency <3 sec for ≥98% of web check-in sessions NDC API retries during high-volume check-in peaks (T-24h departure) cause duplicate offer display or blank offer panels, degrading conversion rate
3.2 Send targeted upsell email and push notifications Email open rate ≥28%; push notification click-through rate ≥12% Altéa CRM notification engine does not suppress duplicate messages when passengers have both web and mobile sessions active, leading to over-communication complaints
3.3 Display upgrade prompts at airport check-in and kiosk Airport upgrade conversion rate ≥8% of prompted passengers SITA AMS kiosk software version lag (often 2+ major releases behind) causes offer display failures on older kiosk hardware at smaller outstations ⚠
4.1 Process upgrade payment via preferred channel Payment processing success rate ≥98.5%; transaction time <10 sec Altéa EMD issuance for upgrade payments using loyalty currency (miles + cash) requires manual fare recalculation when the loyalty system API returns stale balance data ⚠
4.2 Reassign seat and update PNR cabin class PNR update latency <5 sec; zero duplicate seat assignment errors per 10,000 upgrades Concurrent upgrade processing for the same flight can cause seat-map race conditions in Altéa when two agents process the last available premium seat simultaneously
4.3 Provision premium cabin services and lounge access Premium service provisioning lead time ≥45 min before departure for ≥95% of upgrades Catering uplift amendments post-upgrade are frequently missed when the upgrade is processed inside the catering finality window (T-2h), resulting in insufficient premium meals
4.4 Send upgrade confirmation and boarding pass to passenger Confirmation delivery within 60 sec of PNR update for ≥99% of upgrades Mobile boarding pass push fails for passengers using third-party wallet apps (non-Apple/Google Wallet) when Altéa PKPass API returns certificate validation errors
5.1 Aggregate upsell revenue and conversion metrics Upsell revenue per available seat ≥$12 on applicable routes; daily report SLA <6h after day-end EMD revenue attribution in AWS Redshift is delayed by up to 4h due to batch ingestion from Altéa, preventing same-day intra-day optimisation of pricing parameters
5.2 Compare actuals vs. forecast upsell revenue targets Upsell revenue forecast accuracy within ±10% of actuals on rolling 7-day basis Tableau dashboards pulling from AWS Redshift frequently timeout on full-network route-cluster queries, forcing analysts to run ad-hoc SQL instead of using governed reports ⚠
5.3 Recalibrate WTP model and pricing parameters WTP model recalibration cycle ≤7 days after conversion target miss; post-recalibration lift ≥5% PROS RM model retraining requires a minimum 90-day historical acceptance dataset; insufficient data on new routes or post-schedule-change periods degrades model quality for at least one quarter
