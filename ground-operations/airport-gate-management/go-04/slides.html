StepL4 Step Name KPI / TargetPain Point / RiskGate
1.1 Import scheduled movements & gate inventory Gate plan build initiated ≥18h before day of operations; 100% of scheduled movements imported Late schedule amendments from airline ops (within T-6h) invalidate pre-built plans; no automated re-trigger of optimisation on change
1.2 Execute automated gate assignment optimisation ≥92% of flights auto-assigned without manual intervention; optimisation run time <10 min Wide-body/narrow-body gate incompatibility not always captured in AMS master data — results in invalid auto-assignments requiring manual correction
1.3 Validate assignments against aircraft type constraints 0 gate/aircraft-type mismatches published; validation complete ≥14h before operations day Ad-hoc aircraft swaps driven by AOG maintenance events are not always reflected in Amadeus Altéa PSS in time for gate validation cycle ⚠
1.4 Coordinate gate pre-conditioning with terminal ops Gate confirmed ready ≥30 min before scheduled arrival; pre-conditioning exceptions <5% Cleaning and catering subcontractor SLA gaps at high-frequency turn stations cause gate hold-backs; A-CDM milestones not enforced contractually at all airports
1.5 Publish gate plan to FIDS and stakeholder systems Published ≥12h before day of operations; 100% of gates reflected in FIDS within 90 seconds of publish SITA FIDS update latency (up to 90s per change batch) causes passenger confusion during rapid same-day gate changes at high-traffic terminals
2.1 Ingest real-time flight status via ACARS ETA refresh cycle ≤5 min; ETA data completeness ≥97% of active flights ACARS signal dropout over oceanic routes causes ETA gaps; fallback to secondary radar feed introduces 15-min lag and degrades conflict detection accuracy
2.2 Confirm or revise gate assignments from updated ETAs Gate confirmed ≥60 min before scheduled arrival; <5% of gates reassigned day-of A single wide-body delay cascades into 3+ narrow-body gate conflicts as sequential turns are displaced — AMS does not auto-resolve cascades, requiring manual controller intervention ⚠
2.3 Notify ground handling of confirmed gate assignments Notification sent ≥45 min before arrival; stakeholder acknowledgement rate ≥95% Multiple ground handling subcontractors operating on different messaging platforms (SITA, WhatsApp, VHF radio) — fragmented comms increase risk of missed gate changes
3.1 Detect gate conflict from delay or early arrival Conflict detected ≥45 min before arrival; 0 aircraft held on apron >15 min due to gate unavailability Default AMS conflict alerting threshold is 10 min — fails to catch rolling delay sequences that compound over a 3-hour window at hub airports ⚠
3.2 Assess remote stand and bus bridge feasibility Decision made within 10 min of conflict detection; remote stand option assessed for 100% of conflict alerts Limited bus fleet at congested regional airports makes remote stand assignment impractical for wide-body aircraft loads; no real-time bus availability feed integrated into AMS ⚠
3.3 Execute gate swap or remote stand assignment Gate swap communicated to all parties within 5 min of decision; AMS record updated within 60 seconds Gate swap triggers manual re-notification to 6+ parties (handler, fueller, caterer, crew bus, security, cleaning) — no single-button broadcast in current AMS configuration
3.4 Update FIDS, departure boards, and airline mobile app FIDS updated within 2 min of gate change; mobile app push notification delivered within 3 min Airline mobile app gate change notification requires a PSS API round-trip through Amadeus Altéa — up to 4-min latency under peak load causes passengers to board at wrong gate
4.1 Monitor aircraft block-on time and turnaround milestones Block-on captured within 2 min of actual; on-time departure (D0) ≥78% ACARS block-on message can arrive up to 3 min after actual wheel-stop, distorting D0 measurement and masking genuine late-departure root causes in performance reporting
4.2 Validate all ground services complete before release All services signed off ≥10 min before STD; late-service exception rate <3% of turns Paper-based sign-off by some catering subcontractors is not captured in AMS in real time — supervisor must chase confirmation manually, adding 5–8 min to gate release process ⚠
4.3 Authorise pushback and release gate in AMS Gate released within 5 min of block-off; gate turnaround time ≤planned TAT per aircraft type Apron congestion at airports with single-taxiway layouts (common at secondary regional ports) delays pushback clearance from Apron Control, extending occupied gate time beyond planned TAT
5.1 Record and warehouse actual gate utilisation times Data completeness ≥99% of movements; report available within 2h of operations day close AMS-to-Redshift ETL pipeline runs nightly batch — intraday utilisation analysis not available, preventing same-day corrective action on emerging gate congestion patterns
5.2 Analyse gate conflict frequency and root causes ≥80% of recurring gate conflicts identified with actionable root cause within 48h of operations day Delay root-cause data is siloed across SITA AMS, Amadeus Altéa PSS, and crew management system — manual correlation required; no automated attribution pipeline in place
5.3 Update gate constraint and master data in AMS Master data update cycle ≤7 days from change identification; 0 gate conflicts caused by stale constraint data in rolling 90-day window No automated synchronisation between airline fleet database (reflecting aircraft type changes) and AMS gate constraint tables — changes must be re-keyed manually, introducing error risk
