StepL4 Step Name KPI / TargetPain Point / RiskGate
1.1 Ingest booking & transaction data from PSS Data pipeline SLA: 100% of prior-day records ingested by 04:00 local Altéa PNR schema changes on major releases can silently break field mappings, causing downstream profile gaps until the next data audit cycle
1.2 Collect loyalty programme interaction events Event capture rate ≥99% of Salesforce Marketing Cloud triggers per day Loyalty tier change events arrive asynchronously from PSS; without an event-ordering layer, a customer can receive a downgrade communication before the upgrade is confirmed
1.3 Capture web & mobile behavioural data Tag coverage ≥98% of key conversion pages; session data latency ≤2 hours iOS ATT (App Tracking Transparency) and Safari ITP limit cross-device identity stitching, reducing identifiable behavioural profiles by ~20–30% on Apple devices
1.4 Validate data completeness across all sources Overall data completeness ≥95% before downstream processing proceeds GDS-originated bookings (Sabre, Travelport, Amadeus GDS) often arrive with partial passenger profile fields; missing DOB or contact email breaks identity resolution ⚠
2.1 Cleanse and deduplicate customer records Duplicate record rate ≤0.5% post-cleanse; address standardisation accuracy ≥97% Passengers booking via third-party OTAs (Expedia, booking.com) often have name/email variations that resist standard matching rules, inflating duplicate counts
2.2 Verify PII consent and GDPR / CCPA compliance 100% of records processed against current consent status before any marketing activation; consent sync latency ≤24 hours from collection event Consent revocation must propagate to Salesforce Marketing Cloud, Adobe Experience Platform, and Braze within the 72-hour GDPR window — cross-system latency routinely misses this SLA without automated orchestration ⚠
2.3 Enforce data retention and right-to-erasure rules Right-to-erasure requests fulfilled within 30 days per GDPR Article 17; 100% completion rate Cascading deletes across Altéa PSS, Salesforce Marketing Cloud, Adobe Experience Platform, and AWS Redshift require coordinated API calls; partial deletions create residual PII exposure
3.1 Resolve identity and stitch cross-channel profiles Identity match rate ≥80% of known travellers; profile stitching latency ≤6 hours from data ingestion Passengers using travel agent bookings have no direct loyalty ID in the PNR, requiring probabilistic name+route matching which has a ~12% false-positive rate without additional signal ⚠
3.2 Compute customer lifetime value and tier segments CLV model R² ≥0.72; tier classification refreshed weekly; top-decile CLV customers identified for proactive retention Frequent-flyer programme changes (e.g., move from segment- to revenue-based earning) invalidate historical CLV models requiring full retraining — a 3–4 week disruption to personalisation pipelines
4.1 Run customer segmentation models Silhouette score ≥0.55 for k-means clusters; segment refresh cycle ≤7 days Seasonal demand patterns (holidays, school breaks) cause segment drift that is difficult to distinguish from genuine behavioural change — misclassification drives irrelevant offers during peak booking windows ⚠
4.2 Build propensity scores for ancillary and upgrade offers AUC ≥0.75 per propensity model; score refresh ≤48 hours before scheduled departure Short-haul domestic passengers have sparse ancillary purchase histories, causing propensity models to default to population averages and suppressing personalisation lift on high-frequency leisure routes ⚠
4.3 Score churn risk for loyalty programme members Churn model recall ≥70% on held-out validation set; High-risk members flagged ≥60 days before predicted lapse Alliance-free carriers have no partner accrual data to detect cross-airline defection; churn signals are visible only after the customer has already reduced flying frequency, limiting intervention window
5.1 Generate personalised pre-trip offer packages Offer relevance score ≥70% (measured by click-through proxy); ancillary attach rate uplift ≥8% vs control ATPCO-filed fare class restrictions may invalidate upgrade offers at activation time — without real-time inventory checks against Amadeus NRM, irrelevant offers are served, eroding customer trust ⚠
5.2 Activate offers across email, app push, and web Email open rate ≥28%; push notification opt-in rate ≥45%; web personalisation CTR ≥4% Channel fatigue from overlapping CRM, loyalty, and operational email streams — without cross-channel frequency capping in Braze, customers in high-propensity segments receive 5–8 emails per week, driving unsubscribe rates above 0.6%
5.3 Serve real-time personalisation at airport touchpoints Kiosk upgrade conversion rate ≥5% for High-propensity customers; offer display latency ≤500ms from check-in event Real-time inventory sync between Amadeus Altéa PSS and SITA AMS kiosks can lag by 2–4 minutes during peak check-in, causing declined upgrade offers that had already been verbally accepted at the counter ⚠
6.1 Track offer redemption and revenue attribution Incremental ancillary revenue per personalised journey ≥€12 vs control; attribution model updated weekly Last-click attribution in Salesforce Marketing Cloud over-credits email and under-credits app push and airport kiosk touchpoints — multi-touch attribution requires custom AWS Redshift modelling not available out-of-the-box
6.2 Analyse A/B test results and model performance A/B test statistical significance ≥95% before rolling out winning variant; model performance reviewed bi-weekly Small holdout sizes on low-frequency routes (e.g., thin regional services) prevent statistical significance from being reached within a single IATA season, forcing carry-over decisions based on directional data only ⚠
