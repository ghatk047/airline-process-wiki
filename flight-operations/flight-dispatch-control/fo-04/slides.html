1.1 Pull aircraft DOW/DOI from maintenance system Configuration accuracy 100%; zero dispatches with incorrect DOW Last-minute aircraft swaps (e.g., 737-800 replaced by 737-700) cause DOW discrepancy if AMOS weight record not updated within 30 min of tail reassignment
1.2 Retrieve fuel uplift from flight planning system Fuel data transfer latency < 5 min from dispatch plan release Manual re-entry required when API link between Lido/Flight and SITA LoadManager is unavailable; transcription errors produce erroneous TOW calculations
1.3 Calculate structural limits and underload allowance Underload figure accuracy ±50 kg versus final actuals MZFW and MTOW vary by 737 sub-variant (e.g., 737-800 vs 737-8 MAX); incorrect variant code in LoadManager causes structural limit overrun risk without automated alert ⚠
2.1 Extract PAX counts from check-in at cutoff Cutoff-to-load-sheet cycle time < 15 min Late check-in waivers granted after cutoff add PAX to Altéa without auto-alerting load controller; controller may issue load sheet based on stale PAX count
2.2 Apply IATA standard or actual PAX weights Weight deviation vs actuals < 2% for domestic routes Incorrect season flag (summer/winter) in SITA LoadManager causes systematic 4 kg/PAX under-estimate on narrow-body routes with no automated audit trail for season changes ⚠
2.3 Capture checked baggage weights at bag room Baggage weight reconciliation ≥ 99% of tagged bags per flight Individual baggage weighting not performed on narrow-body short-haul; weight estimated from PAX count × standard bag weight, resulting in actual vs plan variance exceeding 200 kg on full flights
2.4 Process special PAX categories from SSR codes SSR compliance rate 100%; zero unmanaged special PAX categories at load sheet issue EXST (extra seat) PAX body weight not consistently captured in Altéa SSR; load controller must query gate agent manually, adding 5–10 min and creating CG error risk
3.1 Receive cargo manifest and ULD build data Cargo manifest received ≥ T-60 min before departure; late manifest rate < 5% Belly cargo manifest routinely received < T-30 min for connection flights; load controller must estimate cargo weight, creating CG shift risk if actuals differ by more than 150 kg ⚠
3.2 Validate and approve DG load — issue NOTOC DG NOTOC issued to captain ≥ T-30 min before departure; 100% ICAO Annex 18 compliance Late DG declarations from freight forwarders cause NOTOC amendments after load sheet issue; each amendment requires captain re-signature, adding 10–20 min average delay ⚠
3.3 Allocate hold bay loading positions for CG target CG within ±1% MAC of target after initial bay allocation Manual bay allocation for 737 holds (bays 41F/42G/43H) is error-prone; no automated CG feedback loop in LoadManager until all weights are confirmed, delaying detection of CG exceedance
4.1 Generate preliminary e-LoadSheet with ZFW/TOW/LDW Preliminary load sheet ready ≥ T-30 min before scheduled departure Tankering fuel decisions made by dispatch after preliminary load sheet generation require full recalculation; re-issue cycle adds 5 min and risks version mismatch between load controller and captain
4.2 Validate CG within certified flight envelope CG out-of-envelope rate < 0.01% of departures (IATA industry benchmark) Aft CG limit exceedance on 737-800 with full cabin and light belly cargo is a known risk scenario; redistribution or trim ballast adds 15–25 min to turnaround time ⚠
4.3 Calculate stabiliser trim setting and confirm CG index Stab trim setting issued to flight deck ≥ T-20 min before departure Discrepancy between load controller stab trim (SITA) and EFB-computed value (Jeppesen FliteDeck) when aircraft config tables are not synchronised; manual cross-check adds 3–5 min per occurrence
4.4 Transmit final load sheet to flight deck via ACARS Load sheet delivery ≥ T-20 min before departure; ACARS receipt confirmation within 2 min ACARS transmission failure at remote stands without ground-to-aircraft data link requires manual paper load sheet handoff, breaking the e-signature audit trail required under ICAO Annex 6
5.1 Captain reviews and signs load sheet on EFB Captain acceptance cycle time < 5 min; load sheet rejection rate < 0.5% Captain queries on ZFW discrepancy require callback to load controller; FliteDeck has no in-app messaging, forcing VHF or phone communication and adding average 4 min delay per query ⚠
5.2 Issue final loading instruction and close holds Hold closure notification ≥ T-10 min before departure; D0 on-time departure impact attributable to W&B < 0.3% Late passenger offloads (IROPS, no-show reconciliation) after hold closure require baggage pull, repeat CG validation, and captain re-acceptance — average additional delay 20 min per occurrence ⚠
5.3 Archive load sheet and transmit LDM to destination LDM transmitted within 5 min of actual departure; 100% archival compliance rate LDM is not auto-transmitted when SITA LoadManager is in failover mode; manual Telex composition is error-prone and causes destination station misinterpretation of hold contents
